Техническое Задание и Roadmap Проекта (на основе Концепции)Этот документ развивает "Первоначальную концепцию проекта" и предлагает конкретную архитектуру, стек технологий и поэтапный план для реализации.1. Ключевые Архитектурные РешенияПроанализировав вашу концепцию, предлагаются следующие решения по ключевым вопросам (пункты 1, 2, 5 из концепции).A. Стратегия Парсинга (Пункт 1)Решение: Гибридный подход.Это комбинация ваших "Варианта А" и "Варианта Б", которая минимизирует недостатки каждого.Парсинг "по требованию" (On-Demand):Механика: Менеджер делает запрос -> Browser MCP / Browser Use агенты в реальном времени заходят на 10-20 сайтов поставщиков и собирают данные.Плюс: Всегда 100% актуальная информация о наличии и цене.Минус: Занимает 1-3 минуты на выполнение запроса.Приоритет: Это MVP (Minimum Viable Product). С этого нужно начать.Регулярный Парсинг (Фоновый):Механика: Ежедневно (ночью) парсеры собирают данные только по самым популярным, высоко-оборачиваемым деталям (фильтры, масла, тормозные колодки для популярных моделей).Плюс: Мгновенный ответ по 80% самых частых запросов.Минус: Не покрывает редкие детали.Приоритет: Это Phase 2 (Оптимизация). Внедряется после MVP.B. Технологический Стек (Пункт 5)Оркестратор (Orchestration): n8n (как вы и предложили). Идеально подходит для связывания всех модулей (Webhook -> Browser Agents -> AI -> Telegram).Веб-Автоматизация: Browser MCP / Browser Use. Ядро для сбора данных "по требованию".AI-Анализ: Gemini API. Будет принимать структурированные данные от парсеров и генерировать сводку.Часть 1 (БД для кеша): Redis. Идеален для фонового парсинга (хранение пар "Артикул:Цена/Наличие" с TTL 24 часа).Часть 2 (B2B-Бот): Telegram Bot API + Node.js (или Python/FastAPI) бэкенд + Firebase (Firestore).Firebase/Firestore отлично подходит, так как это NoSQL БД в реальном времени, что упростит управление магазинами, их подписками и чатами.C. Выход для Менеджера (Markdown в Telegram):AI (MCP) должен сгенерировать краткую, ясную сводку:Запрос: Фильтр масляный (A-12345)🏆 Рекомендация (Лучший баланс):Поставщик А | 1500 руб | 1 деньПерейти к заказу⚡️ Самый быстрый:Поставщик В | 1600 руб | В наличииПерейти к заказу💰 Самый дешевый:Поставщик Б | 1450 руб | 3 дняПерейти к заказу[Опционально: Ссылка на PDF/Google Sheet со всеми 20+ вариантами]2. Декомпозиция и Roadmap (Пункт 6)Предлагается 4-этапный план релиза.Phase 0: MVP 1 (Ядро Парсинга)Цель: Дать менеджеру рабочий инструмент для автоматизации Части 1 (On-Demand).[ ] 1. Идентификация Артикулов: Настроить интеграцию (API или парсинг) с 1 каталогом (например, exist.ru) для получения точных артикулов по Марке/Модели/VIN.[ ] 2. Настройка Browser Agents: Настроить Browser Use для парсинга 3-5 ключевых поставщиков.[ ] 3. Настройка AI-Анализа: Создать MCP (промпт) для Gemini, который принимает JSON (см. выше) и генерирует Markdown-сводку.[ ] 4. Сборка n8n Workflow:Создать Telegram-бота для менеджера.Workflow: Менеджер пишет боту /find [VIN] [название детали] -> Запрос в каталог -> Получение артикулов -> Запуск Browser Agents (параллельно) -> Агрегация JSON -> Отправка в Gemini -> Отправка Markdown-сводки менеджеру.Phase 1: MVP 2 (B2B-Сеть)Цель: Протестировать гипотезу быстрой B2B-доставки (Часть 2). Можно делать параллельно с Phase 0.[ ] 1. Архитектура Бота (Пункт 3):Создать второго Telegram-бота (B2B-Net-Bot).Бэкенд на Node.js + Firebase.[ ] 2. Управление Магазинами:Реализовать FSM (Finite State Machine): /start -> Регистрация магазина (Название, Адрес, Контакт).Админка для одобрения новых магазинов.[ ] 3. Механика Запроса (Broadcast):Менеджер (через своего бота из Phase 0) нажимает кнопку "Опросить B2B-сеть".B2B-Net-Bot делает broadcast-сообщение всем одобренным магазинам.[ ] 4. Механика Ответа:Магазин видит запрос и нажимает "Ответить".Бот задает вопросы (в личном чате): "Цена?", "Наличие/Срок?".Все ответы агрегируются и присылаются менеджеру в реальном времени.Phase 2: Интеграция и ОптимизацияЦель: Связать системы и внедрить кеширование.[ ] 1. Интеграция: Умная кнопка "Опросить B2B-сеть" появляется у менеджера только если Часть 1 дала плохие результаты (дорого / долго).[ ] 2. Гибридный Парсинг:Настроить Redis.Создать n8n-воркфлоу, который запускается каждую ночь.Он парсит топ-1000 артикулов и складывает результаты в Redis с TTL=24h.[ ] 3. Визуализация (Пункт 7):Интегрировать n8n с Trello/ClickUp (или кастомным UI).Каждый запрос менеджера = новая карточка.Колонки: "Новый" -> "Идет парсинг (Browser Agents)" -> "Анализ AI" -> "Опрос B2C (Опционально)" -> "Готово".Это даст менеджеру "визуализацию этапов работы".Phase 3: Масштабирование и МонетизацияЦель: Расширение и начало монетизации B2B-сети (Пункт 4).[ ] 1. Монетизация B2B:Реализовать функционал для магазинов-подписчиков: "Сделать свой broadcast-запрос" (поиск деталей у соседей).Внедрить модель: N бесплатных запросов в месяц, далее — платная подписка.[ ] 2. Масштабирование Парсинга:Добавить +20 сайтов поставщиков.Внедрить ротацию прокси-серверов для парсеров.[ ] 3. Улучшение AI:Обучить AI учитывать "надежность поставщика" (на основе статистики прошлых заказов).3. Следующие ШагиУтвердить/скорректировать предложенный Roadmap.Начать разработку Phase 0: MVP 1.Зарегистрировать 2 Telegram-бота (для менеджера и для B2B-сети).Собрать список из 3-5 ключевых поставщиков (для MVP 1) и получить доступы к их сайтам.
