# 📋 Первоначальная концепция проекта

## 🏢 Бизнес-контекст

**Текущая ситуация:**
- Автосервис (шиномонтажка) развивает направление продажи запчастей
- Менеджер вручную подбирает запчасти для клиентов
- Процесс: мониторинг сайтов крупных поставщиков → предложение вариантов клиенту
- Критичные факторы при выборе: **наличие** (в наличии vs под заказ), **цена**, **сроки доставки**

**Проблема:** Процесс трудоемкий, требует постоянного ручного мониторинга множества источников

---

## 💡 Концепция решения

### **Часть 1: Автоматизация поиска у поставщиков**

#### Этап 0: Определение номенклатуры
- Интеграция с каталогами (например, **exist.ru**)
- По марке/модели автомобиля получить точные артикулы деталей
- Формирование корректного списка для поиска

#### Этап 1: Сбор данных о ценах и наличии

**Варианты реализации (требуется обсуждение):**

**Вариант А: Регулярный парсинг + собственная БД**
- Ежедневный парсинг 10-20+ сайтов поставщиков
- Ведение актуальной базы цен и наличия
- **Проблема:** Большой объем данных, много редко запрашиваемых деталей (специфичные марки авто)

**Вариант Б: Парсинг по требованию**
- Единоразово собрать ассортимент поставщиков
- При запросе использовать **Browser MCP** или **Browser Use**
- Агенты заходят на конкретные карточки товаров по списку сайтов
- Создают сводку: PDF / скриншоты с указанием источников

*Требуется проработка формата вывода данных*

#### Этап 2: AI-анализ и формирование рекомендаций
- AI обрабатывает всю выборку данных
- Анализ по критериям: цена, сроки, надежность поставщика
- **Выход:** Обоснованные рекомендации лучших вариантов
- Формат: PDF-отчет / структурированный файл / другое (обсудить)

#### Этап 3: Доставка результата менеджеру
- Отправка заключения в **Telegram**
- Включение прямых ссылок на сайты поставщиков
- Менеджер может быстро перейти и оформить заказ

---

### **Часть 2: Локальная B2B-сеть магазинов**

#### Концепция
- В радиусе ~60 км находятся магазины запчастей (другие города)
- Реализация: **Telegram-бот** или **мини-приложение**

#### Механика работы
1. Магазины подписываются на бота
2. При запросе все магазины **одновременно** получают broadcast
3. Отвечают о наличии и цене
4. Каждый магазин имеет **личное** общение с ботом

#### Преимущество
- **Скорость:** Сотрудник может забрать деталь на машине в течение часа
- Альтернатива ожиданию доставки от крупных поставщиков

#### Монетизация
- Возможность для магазинов самим делать broadcast соседям
- *Модель монетизации требует проработки*

## 🛠️ Технологические акценты

**Ключевые инструменты для рассмотрения:**
- **MCP (Model Context Protocol)** - активное использование
- **Browser MCP / Browser Use** - для автоматизации веб-навигации
- **n8n** или альтернативы - для orchestration и автоматизации
- **Визуализация процессов:**
  - Отображение этапов работы агента (thinking)
  - Kanban-доски для отслеживания статусов

**Готовые решения:**
- Изучить существующие инструменты для визуализации AI-агентов
- Рассмотреть интеграцию готовых каталогов запчастей
