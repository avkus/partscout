## Вопрос архитектору проекта

### Почему я изначально склонялся к использованию MCP-архитектуры?

#### 1. Нативная поддержка MCP в современных AI-инструментах

**Gemini CLI** и **Qwen Code CLI** (написанный на его основе) имеют встроенную поддержку Model Context Protocol, аналогично **Claude Desktop**. Это означает, что MCP уже является стандартом де-факто для интеграции AI-агентов с инструментами.

#### 2. Глобальные системные инструкции

**Gemini CLI** поддерживает настройку глобальных системных инструкций, что позволяет:
- Единожды настроить поведение AI для специфики проекта
- Использовать одинаковую логику работы во всех точках взаимодействия
- Обеспечить консистентность ответов системы

#### 3. Удобство для разработчика

Как разработчик, я могу работать непосредственно в **VS Code** с использованием плагина **Gemini CLI Companion**. Это обеспечивает:
- Бесшовную интеграцию в процесс разработки
- Возможность тестирования MCP-серверов прямо в IDE
- Быструю отладку системных инструкций и промптов

#### 4. Простота для менеджера (конечного пользователя)

На компьютере менеджера можно установить **Gemini CLI**, и ему будет достаточно:
- Написать простой текстовый запрос в командной строке
- Получить результаты по различным каналам доставки (Telegram, Email, PDF)
- Не разбираться в технических деталях реализации

Это значительно снижает порог входа для пользователя и не требует разработки отдельного UI.

#### 5. Гибкость каналов доставки результатов

Система может отправлять результаты по разным каналам:
- **Менеджеру:** Telegram (быстрое уведомление с данными)
- **Клиенту:** Email с фирменным PDF-отчетом
- **Альтернативные каналы:** SMS, мессенджеры и т.д.

#### 6. Абстракция для клиента

Клиенту **не обязательно знать**, какого поставщика мы выбрали или как происходил поиск. Мы формируем **фирменный профессиональный отчет** с лучшими вариантами, который:
- Содержит брендированный дизайн автосервиса
- Представляет готовые рекомендации
- Может быть отправлен в личный Telegram клиента или на Email
- Скрывает техническую сложность процесса подбора

### 5. **Гибкость каналов доставки**

```python
# MCP Server: notify-server

@server.tool()
async def send_result(
    report_path: str,
    channels: List[str],  # ["telegram", "email", "sms"]
    recipients: dict
):
    """Отправка результата по разным каналам"""
    
    if "telegram" in channels:
        await send_telegram(
            chat_id=recipients["manager_chat_id"],
            document=report_path,
            caption="✅ Подбор завершен"
        )
    
    if "email" in channels:
        await send_email(
            to=recipients["client_email"],
            subject="Подбор запчастей Toyota Camry",
            attachment=report_path,
            template="client_report"
        )
    
    if "sms" in channels:
        await send_sms(
            phone=recipients["client_phone"],
            text="Запчасти подобраны. Проверьте email."
        )
```

**Сценарии использования:**

```
Менеджер через CLI:
└── Получает в Telegram (быстро, с ссылками)

Автоматизация n8n:
├── Менеджеру в Telegram
└── Клиенту на Email (фирменный PDF)

Срочный запрос:
├── Менеджеру в Telegram
├── Клиенту SMS (уведомление)
└── Клиенту Email (детали)
```

```
1. MCP Серверы = Бизнес-логика (переиспользуемая)
   ├── Один раз написали
   └── Используется везде (CLI, API, n8n, Telegram)

2. Клиенты = Интерфейсы (взаимозаменяемые)
   ├── Gemini CLI (быстрый доступ)
   ├── Telegram Bot (мобильность)
   ├── FastAPI (интеграции)
   └── n8n (автоматизация)

3. Протокол = Стандарт (независимость)
   └── Можем менять и серверы, и клиентов
```
