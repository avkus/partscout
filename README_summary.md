## 🎯 О проекте

**PartScout** — система автоматизации подбора автозапчастей с использованием AI-агентов для автосервисов и шиномонтажек на белорусском рынке.

### Ключевые возможности

- 🤖 **AI-анализ через Gemini 2.0** - автоматический поиск и сравнение от 10+ поставщиков
- 🌐 **Работа в РБ/РФ** - обход ГЕО-блокировки через Cloudflare Proxy
- ⚡ **Скорость** - сокращение времени подбора с 30-40 минут до 2-3 минут
- 🔄 **Гибридные режимы** - полностью автоматический, полуавтомат, ручной с помощником
- 💡 **Умный CLI** - автокоррекция запросов, помощь в формулировке
- 🇧🇾 **Белорусские каталоги** - интеграция с auto1.by, armtek.by
- 🧠 **RAG для обучения** - система накапливает знания и становится умнее
- 🔌 **MCP-first** - переиспользуемые компоненты через Model Context Protocol
- 📱 **Telegram интеграция** - удобный интерфейс для менеджеров
- 🌍 **Локальная B2B сеть** - интеграция с магазинами в радиусе 60км (Phase 2)

### 📝 Ключевые архитектурные решения

#### 1. MCP-first подход
**Решение:** Вся бизнес-логика в виде MCP серверов

**Причины:**
- Gemini CLI и Qwen Code CLI имеют нативную поддержку MCP
- Универсальный интерфейс (CLI, Telegram, n8n, API)
- Переиспользование компонентов
- Легкое тестирование в VS Code (Gemini CLI Companion)

**Список MCP серверов:**
```
1. catalog-server - работа с каталогами (auto1.by, armtek.by)
2. browser-server - парсинг сайтов через Playwright
3. analysis-server - AI анализ предложений (Gemini)
4. report-server - генерация PDF/Markdown отчетов
5. supabase-server - операции с БД
6. notify-server - уведомления (Telegram, Email)
7. assisted-search-server - помощник в формулировке запросов
8. manual-mode-server - полуавтоматический режим
9. rag-server - работа с embeddings и векторным поиском
10. b2b-server - локальная сеть магазинов (Phase 2)
```

#### 2. Gemini Proxy для обхода ГЕО-блокировки

**Проблема:** Gemini API недоступен в BY/RU

**Решение:** Cloudflare Workers прокси
- Развернут на `https://cf-gemini-proxy.avkus.workers.dev`
- Round-robin ротация между несколькими API ключами
- Durable Objects для сохранения состояния
- Выбор между Nginx и Vercel прокси

**Использование:**
```python
client = genai.Client(
    api_key=GEMINI_API_KEY,
    base_url=GEMINI_PROXY_URL,
    headers={"X-Master-Key": GEMINI_PROXY_MASTER_KEY}
)
```

#### 3. Гибридный подход к парсингу

**Проблема:** API не всегда доступны, данные быстро устаревают

**Решение:** Три стратегии в зависимости от ситуации

```
Стратегия А: API каталогов (auto1.by, armtek.by)
└── Быстро, структурировано, надежно
└── Используется когда доступно

Стратегия Б: Кэш + селективный парсинг
└── Популярные детали → кэш в Supabase (TTL 6-24ч)
└── Редкие детали → парсинг по требованию

Стратегия В: Полуавтоматический режим
└── Менеджер дает URL страниц вручную
└── Система парсит, анализирует, сохраняет в RAG
└── Постепенное обучение системы
```

#### 4. RAG для накопления знаний

**Что хранится в RAG:**

```
Google Drive / PartScout /
├── /Маппинги поставщиков/
│   ├── Excel прайсы → SQL в Supabase
│   └── Артикул → URL соответствия
│
├── /База знаний/
│   ├── Совместимость деталей → Embeddings
│   ├── Частые вопросы → Embeddings
│   └── Лучшие практики запросов → Embeddings
│
└── /Обучение менеджера/
    └── Как правильно формулировать запросы
```

**n8n Workflow (уже реализован):**
1. Мониторит Google Drive на изменения
2. Excel → парсит и загружает в Supabase (SQL доступ)
3. PDF/MD/DOCX → создает embeddings через Gemini
4. Сохраняет в Supabase pgvector
5. AI агент выбирает инструмент: SQL или векторный поиск

#### 5. Белорусские каталоги

**Решение:** Приоритет auto1.by и armtek.by

**Каталоги для интеграции:**

| Каталог | Приоритет | Возможности | API |
|---------|-----------|-------------|-----|
| **auto1.by** | 1 | Поиск по артикулу/бренду, запасы на складах | WebAPI (требуется авторизация) |
| **armtek.by** | 2 | VIN-декодирование, подбор по марке/модели | API (требуется ключ) |
| zapchasti24.by | 3 | Онлайн подбор | Уточняется |
| av-parts.by | 4 | Резерв | Парсинг |

**Статус:** Ожидаем тестовый доступ к API

#### 6. Три режима работы для менеджера

**Режим А: Полностью автоматический**
```
Менеджер → "Масляный фильтр Toyota Camry 2015"
         ↓
Система → Каталог → Парсинг → Анализ → Отчет (2-3 мин)
         ↓
Менеджер получает готовые рекомендации
```

**Режим Б: Полуавтоматический (гибридный)** ⭐
```
Менеджер → Находит страницы на сайтах вручную (5-10 URL)
         ↓
Вставляет в систему → Система парсит → Анализирует → Отчет
         ↓
RAG сохраняет связь (артикул → URL) для будущего
         ↓
Следующий раз эти URL проверяются автоматически
```

**Преимущества полуавтомата:**
- ✅ Работает с ЛЮБЫМИ сайтами (даже без API)
- ✅ Менеджер использует свой опыт
- ✅ Система учится и автоматизируется постепенно
- ✅ Не зависит от доступности API

**Режим В: Ручной с AI-помощником**
```
Менеджер → Пишет с опечатками: "тармазные диски камри"
         ↓
AI → Автокоррекция: "Тормозные диски Toyota Camry"
   → Помощь: "Уточни год автомобиля"
   → Чтение RAG: "Лучшие практики формулировки"
         ↓
Менеджер → Получает подсказки и шаблоны
```

## 🔥 Проблема и решение

### Текущая ситуация

```
Менеджер автосервиса вручную:
├── Определяет нужную деталь по марке авто
├── Открывает 10-15 сайтов поставщиков
├── Сравнивает цены, наличие, сроки доставки
├── Звонит в локальные магазины
└── Тратит 30-40 минут на один запрос
```

**Проблемы:**
- ⏱️ Большие временные затраты
- 😫 Рутинная монотонная работа
- ❌ Человеческий фактор (пропуск выгодных предложений)
- 📉 Невозможность обработать много запросов в день
- 🌐 Сложности с доступом к AI (блокировка Gemini в BY/RU)

### Решение PartScout

```
AI-агент автоматически:
├── Определяет точные артикулы через каталоги (auto1.by, armtek.by)
├── Параллельно проверяет все источники:
│   ├── Онлайн-поставщики (API/парсинг)
│   ├── Кэш в Supabase (быстрые данные)
│   └── Локальные магазины (Telegram broadcast) [Phase 2]
├── Анализирует предложения с помощью Gemini AI (через прокси)
├── Учится из прошлого опыта (RAG)
├── Формирует обоснованные рекомендации
└── Отправляет отчет менеджеру (Telegram/Email/PDF)
```

**Результат:**
- ✅ Время подбора: 2-3 минуты (vs 30-40)
- ✅ Охват всех доступных источников
- ✅ Обоснованные рекомендации от AI
- ✅ Обработка до 50+ запросов/день
- ✅ Работает несмотря на ГЕО-блокировки
- ✅ Постепенное обучение и улучшение

### Краткое резюме проекта

**Что:** AI-система автоматизации подбора автозапчастей для автосервисов  
**Где:** Беларусь (важно: Gemini заблокирован, используем прокси)  
**Стек:** Gemini 2.0 (через CF Workers прокси) + MCP + FastAPI + Playwright + Supabase + n8n  
**Статус:** Research & Architecture фаза, код не начат, ждем интервью с менеджером

### Ключевые архитектурные решения

1. **MCP-first** - вся логика в MCP серверах (catalog, browser, rag, analysis, etc.)
2. **Gemini через прокси** - обязательно (https://cf-gemini-proxy.avkus.workers.dev)

4. **Белорусские каталоги** - auto1.by (приоритет 1), armtek.by (приоритет 2)
5. **RAG для обучения** - n8n мониторит Google Drive, создает embeddings, хранит в Supabase pgvector
6. **Гибридный парсинг** - API когда есть, кэш для популярного, real-time для редкого
